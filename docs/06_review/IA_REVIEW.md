## 1. 导航模型摘要

单窗口桌面应用，无路由/无面包屑，全部状态驱动切换：顶栏（48px，3 按钮）→ 主区（侧栏 280px：连接区 ≤50% + Schema 区弹性）→ 工作区（视图切换器 5 按钮 + 视图容器）→ 状态栏（24px）+ 全局层（Toast 栈 z-2000 / 确认对话框 z-2100 / 未接线批量面板）。

## 3. 问题清单（7 项：B4、C2、D1）

| 编号 | 级别 | 问题 | 摘要 | 建议 |
|------|------|------|------|------|
| IA-01 | B | 「设计表」入口不可从对象菜单直达 | 表右键仅 4 项（刷新/重命名/清空/删除），「能删不能改结构」不对称；现路径须点表进网格→视图切换器两跳 | 右键菜单增加「设计表」 |
| IA-02 | B | 工具视图混入视图切换器，关闭语义不一致 | sync/backup 自带×（→ setViewMode('query')），query/grid/design 无×；× 与 active 按钮状态可能不同步 | 统一二选一：去×或全视图统一关闭行为 |
| IA-03 | B | 「设置」面板名不副实 | 仅静态说明（安全/限制），无可操作项；真实开关（历史本地保存）在编辑器侧栏 | 升级为真设置位，或更名「使用须知」 |
| IA-04 | B | 同能力异位：导出与单元格编辑双归属 | 导出三处三套（P4 PF-11 交叉）；单元格编辑双实现门禁口径不同（P4 PF-10 交叉） | 公共能力统一时同步统一入口位置规范 |
| IA-05 | C | 多库方言能力归属未下沉 driver 层 | Capabilities/Driver trait 空壳；方言逻辑散落 4 视图组件 + 2 命令文件（硬编码 information_schema/引擎/字符集/LIMIT） | P7 将「方言能力声明→UI 可见性/SQL 生成」归 driver 层；是否随 V1 落地由用户定 |
| IA-06 | D-正面 | 侧栏「连接 / Schema」两区结构 | 层级清晰、选中连接激活、系统库过滤 | 不动，V1 延续 |
| IA-07 | C | 批量进度面板（PAGE012）归属未定 | 组件完整无入口（P4 PF-03 交叉）；与确认框/Toast 的 z 序与互斥关系未定义【未知——无运行实例可证】 | 接线方案中明确 z 序（进度面板低于确认对话框） |

## 4. 多数据库类型下的功能归属（评审重点，现状核查）

- 驱动标识：`ConnectionInfo.driver`（serde 名 `driver`），连接表单隐藏固定 `'mysql'`——扩库时需新增驱动选择/端口默认值/方言参数区，现无归属位。
- 元数据：meta_* 硬编码 `information_schema`（SCHEMATA/TABLES/COLUMNS/STATISTICS）——PG/SQLite 需按 driver 分派。
- 表选项：设计器硬编码 MySQL 引擎 5 项/字符集 5 项/排序 7 项——`Capabilities` 已定义未使用。
- 分页/编辑 SQL：硬编码 `LIMIT 50 OFFSET` / `UPDATE … LIMIT 1`——`supports_limit_offset` 已定义未用。
- 结论：扩展预置「类型有、归属无」——trait 与能力字段是空壳（与 PL-05 同源）。

## 5. 小结

信息架构主干（侧栏双区 + 视图切换器 + 全局反馈层）健康；问题集中在三个模式（对象操作入口不随对象走 / 工具与工作视图混容器 / 同能力多归属）。IA-01/02/03 可随 V1 原型低成本落地；IA-04/05 依赖公共能力划分（P5/P7）；IA-07 随 PF-03 接线一并处理。
