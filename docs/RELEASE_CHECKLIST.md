# QueryLab 发布前检查清单

> 适用范围：`QueryLab/`
> 用途：发布前做最小但完整的成品化复核，避免把开发版直接当正式版交付

---

## 发布定位

当前版本应按下面这条边界来对外说明：

- 支持 MySQL / MariaDB
- 支持连接管理、Schema 浏览、SQL 执行、数据网格、表结构编辑
- 支持 SQL 备份导出与 SQL 备份导入
- `结构对比（预览）` 只提供结构差异分析与结构变更 SQL 执行
- 不宣称真实数据同步

如果对外文案超出这条边界，先改文案，再谈发布。

---

## 代码与构建

- [ ] `npm test`
- [ ] `npm run build`
- [ ] `cargo check`（目录：`src-tauri/`）
- [ ] `npm run tauri:dev` 能进入运行态
- [ ] 根工作区与 `src-ui/` 的角色说明没有冲突

推荐命令：

```bash
cd QueryLab
npm test
npm run build
cd src-tauri
cargo check
```

---

## 主流程冒烟

至少手工验证下面 6 条：

1. 新建连接
- [ ] 能输入连接名称、主机、端口、用户、密码
- [ ] 点击“测试连接”能返回明确结果
- [ ] 点击“保存”后连接出现在列表中

2. 重启后连接仍在
- [ ] 关闭应用后重新打开
- [ ] 列表中仍能看到已保存连接
- [ ] 不需要重新录入非敏感元数据

3. Schema 浏览
- [ ] 选中连接后能加载数据库列表
- [ ] 展开数据库后能看到表列表
- [ ] 选择表后能进入数据网格

4. SQL 查询
- [ ] SQL 编辑器可以执行基础 `SELECT`
- [ ] 查询结果面板能显示结果集
- [ ] 批量执行模式至少能执行 2 条语句

5. 数据网格
- [ ] 数据网格能分页
- [ ] 单元格编辑成功后能刷新结果
- [ ] 插入 / 删除一行能正确反馈

6. 备份导入
- [ ] SQL 导出能生成 `.sql` 文件
- [ ] SQL 导入能选择 `.sql` 文件并执行
- [ ] 不再出现 JSON / CSV 导入导出的误导性承诺

---

## 成品化边界

- [ ] 默认连接表单不再预填测试账号密码
- [ ] `结构对比（预览）` 文案明确，不再写成真实同步
- [ ] 备份页明确“当前仅支持 SQL”
- [ ] 关键操作反馈主要走统一通知层，不再依赖大量浏览器 `alert()/confirm()`
- [ ] 没有明显 `/tmp` 调试落盘、console 调试刷屏等开发残留

---

## 安全与配置

- [ ] 连接密码不再写入 `connections.json`
- [ ] 钥匙串可正常读写连接密码
- [ ] SQL 历史默认不做本地持久化
- [ ] 若开启本地历史保存，敏感 SQL 不写入本地历史
- [ ] Tauri 发布配置不再显式暴露开发态选项

---

## 对外说明

发布说明里至少明确：

- 当前支持的数据库类型
- 当前版本不支持真实数据同步
- 当前备份/导入仅支持 SQL
- 已完成哪些核心能力
- 已知限制有哪些

如果发布说明里还在写：

- JSON / CSV 导入导出
- 真实数据同步
- 更多数据库已支持

则说明发布内容仍未收口。

---

## 不通过则不发

下面任一条不通过，建议暂停发布：

- `npm test` / `npm run build` / `cargo check` 任一失败
- 新建连接后重启看不到连接
- Schema 列表看不到表
- SQL 查询无法正常执行
- SQL 备份导出/导入任一失败
- 仍存在明显误导文案：把预览能力说成正式能力
