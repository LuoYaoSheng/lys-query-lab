# QueryLab 用户流程评审（UF）

> 评审依据：《AI 产品重构逻辑评审规范 v1.0》· 2026-09-03
> 输入文档清单：`docs/01_reverse/REVERSE_ANALYSIS.md` §⑥、`docs/02_product/PRD.md` §3/§7/§8、`docs/02_product/PAGE_SPEC.md` §一/§二/§三、`docs/06_review/PRODUCT_REVIEW.md`（P4，PF/FL 编号交叉引用）、源码抽查 `src/App.svelte`、`src/components/ConnectionManager.svelte`、`src/components/DatabaseBackup.svelte`、`src-tauri/src/commands/*.rs`。
> 五要素口径：触发 / 前置 / 步骤 / 结果 / 异常出口。路径对比口径：「最快合理路径」= 同类产品（Navicat/DBeaver 类）惯例最短路径。

## 一、核心流程路径对比（8 条）

### F1 首次连接建立

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 侧栏 ＋ → 填 5 字段 → 测试（可选）→ 保存 → 点连接项（2-3 步） |
| 现路径 | 同左（ConnectionManager：openNewForm → conn_test(可选) → conn_upsert → selectConnection） |
| 对比结论 | 路径形态**符合**最快路径；但带密码账户在「点连接项」后加载库即失败（UF-01，凭据链路断裂，PL-01 交叉） |

### F2 连接 → 浏览 → 查询（主流程）

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 点连接 → 树展开库 → 点表直看数据（3 步）；或点连接 → SQL 视图直接写 SQL → Ctrl+Enter（2 步） |
| 现路径 | 结构同上（handleConnect → loadDatabases → 展开加载表 → 点表切网格 / 编辑器执行） |
| 对比结论 | 路径**符合**；两处体验断点：① 带密码账户在 loadDatabases 即失败（UF-01）；② 点表后想回查询视图会被自动回填 `SELECT * … LIMIT 1000` 覆盖手写 SQL（P4 FL-02 交叉，B 已列） |

### F3 查询 → 保存结果（导出）

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 结果区点「CSV/JSON」→ 系统保存对话框选路径 → 完成（2 步） |
| 现路径 | 点导出 → `save()`（plugin-dialog）→ **打包态必然 reject（插件未注册，PL-02）** → catch 降级 `URL.createObjectURL` 浏览器下载（Tauri webview 内落点不可控） |
| 对比结论 | **不符合**：主路径（原生对话框）不存在，实际永远走降级；文件名在非单表查询时为 `_export.csv`（P4 PF-04 交叉） |

### F4 数据修正（网格定位 → 改数）

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 点表 → 筛选定位 → 双击改 → Enter（3 步） |
| 现路径 | 同左（DataGrid：loadData → 筛选回第 1 页 → 双击 UPDATE…LIMIT 1 → 刷新反馈） |
| 对比结论 | 路径**符合**；Tab 键丢值缺陷 P4 PF-09 已列（交叉）；无单列主键表的只读降级有横幅提示（正面） |

### F5 表结构演进（新建 / 改结构）

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 树右键「设计表」→ 改 → 保存（新建：库下「+ 新建表」） |
| 现路径 | 新建：展开库 → 「+ 新建表」→ 设计器 → 保存 → 自动切网格（合理）；**编辑：无右键入口，须 点表进网格 → 视图切换器「📋 设计表」两跳（IA-01）**；且「关闭」直接丢弃未保存更改（PL-03/UF-05） |
| 对比结论 | 新建**符合**；编辑路径多一跳且意图错位；关闭无异常出口 |

### F6 环境结构对齐（结构对比）

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 选源/目标 → 比较 → 勾选 → 执行（或复制 SQL 出仓）（3-4 步） |
| 现路径 | 同左（DataSync startCompare → 默认全选 → danger 确认 → 逐句执行 → syncComplete 刷新） |
| 对比结论 | 路径**符合**；危险确认与完成刷新齐备（正面）；「新增表仅注释」为承诺边界（P4 FL-08 D，交叉维持） |

### F7 备份导出 / 导入还原

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 导出：选库选表 → 开始 → 保存对话框；导入：选库选文件 → 开始（各 2-3 步） |
| 现路径 | 导出依赖 `save()`（**必然失败**→ 降级下载，PL-02）；导入依赖 `open()` 选文件（**必然失败且无降级**，`importFile` 恒空 → 开始按钮永久禁用，DatabaseBackup.svelte L199-220/L386） |
| 对比结论 | **不符合**：导入流程在打包态第一步就走不通（UF-06）；导出取消路径反馈「已取消导出」是正面细节（P4 FL-10 交叉） |

### F8 批量执行（含事务）

| 维度 | 内容 |
|------|------|
| 最快合理路径 | 开批量开关（+事务）→ 运行 → 看逐条进度与失败项 |
| 现路径 | 开关 → 运行 → `START TRANSACTION;…COMMIT;` 整体提交（App.svelte L185-189）→ 反馈仅状态栏一行「Batch completed: N statements, Xms」；逐条进度面板未接线（P4 PF-03 交叉） |
| 对比结论 | 路径**部分符合**：执行可用，但反馈层缺位（⑦ 号抽查）；事务失败后无 ROLLBACK 显式语句——靠连接关闭隐式回滚，用户无感知【代码路径核实：query_execute 出错即 return，连接 drop；无显式 ROLLBACK】 |

## 三、异常分支专项（评审重点 12：连接失败 / 查询超时 / 权限拒绝）

| 异常场景 | 提示 | 下一步指引 | 可恢复性 | 结论 |
|----------|------|-----------|----------|------|
| 测试连接失败（表单态） | 红块「连接失败: err / 连接超时（5秒）」 | 无直达编辑（P4 FL-01 已列 B：失败块加「编辑连接」） | 改参数重测 | P4 交叉 |
| 测试连接失败（列表态 ⚡） | 红块同上 | 无；且带密码账户此测试**恒失败**（传参无密码，PL-01） | 重输密码（进编辑表单） | UF-01 新增事实 |

## 四、问题清单

### UF-01 带密码连接「测试成功→使用失败」，主链路断裂【B·PL-01 交叉·新事实】
- 当前设计：表单测试携带手输密码（ConnectionManager L91-94）→ 成功；保存后点连接项 → `selectedConnection`（无密码，conn_list skip_serializing）→ `meta_list_databases` 等以空密码认证 → 失败（代码路径核实，未实测）。
- 问题：流程视角的「假阳性入口」——用户被测试成功引导进入工作区，随后第一步即失败，且错误文案（Access denied 原文）不会指向「密码未传递」这一真实原因。
- 影响：核心流程对新用户（带密码账户）100% 中断；排障方向被误导（用户会以为密码输错）。
- 建议方向：同 PL-01（服务端凭据解析）；过渡期可在错误文案中识别 `using password: NO` 并提示重输密码。

### UF-02 SQL 执行无超时无取消，「执行中」态可能无终点【B·P4 FL-05 补充升级】
- 当前设计：`conn_test` 有 5 秒超时（connection.rs L59-64）；`query_execute` 无超时（query.rs 全文无 timeout），前端无 abort（App.svelte executeQuery）；P4 FL-05 将「查询取消」定为 C（需任务架构）。
- 问题：流程五要素的「异常出口」在时间维度缺失——慢查询/锁等待时用户只能无限看着 spinner；与 conn_test 的超时设计形成不一致。
- 影响：流程可终止性缺失；用户体验上等同假死。
- 建议方向：取消（query_cancel）维持 C；但**最小修复**建议升 B：后端加可配置超时（默认如 30s）或前端超时提示与「不再等待」选项。

### UF-03 导出主路径损坏，降级路径无反馈区分【B·PL-02 交叉】
- 当前设计：save() 必然 reject → browserDownload 静默降级（DataGrid L637-646、ResultsPanel L258-296）；用户无从知道文件最终去了哪。
- 问题/影响/建议：见 PL-02；流程层补充：降级发生时应 toast 明示「已使用浏览器下载」。

### UF-04 批量事务失败无显式回滚感知【C·新】
- 当前设计：批量+事务拼 `START TRANSACTION;…COMMIT;` 整体提交（App.svelte L185-189）；中途失败时 query_execute 直接返回错误，事务未 COMMIT，靠连接关闭隐式回滚。
- 问题：回滚是隐式行为，用户看到「Batch execution failed」但不知道「已执行的部分是否已回滚」；片段库中的「事务」模板含 ROLLBACK 注释（SqlEditor snippets L69），暗示用户预期显式回滚语义。
- 影响：批量数据操作的心理安全缺口。
- 建议方向：失败时状态/错误文案明示「事务未提交，已回滚」（或技术上补显式 ROLLBACK）；需确认 mysql_async 连接 drop 的回滚语义【未知——需实测】。

### UF-05 设计器未保存关闭无确认【B·PL-03 交叉】
- 见 PL-03。流程视角：F5 的「异常出口」（用户中途放弃）缺失确认环节。

### UF-06 备份导入文件选择不可用且失败静默【B·PL-02 交叉】
- 见 PL-02；流程视角：F7 第一步即断，且 open() 失败仅 console.error（DatabaseBackup L219-220），「开始导入」按钮禁用无原因解释。

### UF-07 连接类失败提示无下一步指引（工作区态）【C·新】
- 当前设计：加载库失败仅 console（App.svelte L47-49）；查询态连接失败仅错误原文（queryError）；P4 FL-01 仅覆盖表单态测试失败。
- 问题：同类「连接不可达/凭据失效」异常在三个位置（表单测试/加载库/查询执行）有三种反馈强度（红块/静默/错误态），均无「去编辑连接/去重连」直达。
- 影响：异常恢复路径长；静默分支（loadDatabases）甚至让用户以为「无库」。
- 建议方向：统一连接类错误反馈组件（错误码识别 + 直达编辑 + 重试），V1 至少消除 loadDatabases 静默分支。

### UF-08 新建表入口需先展开目标库【C·新】
- 当前设计：「+ 新建表」按钮位于库节点展开区内部（SchemaTree），库未展开时不可见。
- 问题：入口可见性依赖前置展开操作；「+ 数据库」常驻工具栏而「新建表」不是，层级规则不一致（虽有「先有库后有表」的逻辑合理性）。
- 影响：弱；可发现性问题。
- 建议方向：观察或右键库节点加「新建表」；属交互取舍，留用户决策。

### UF-09 危险操作确认链完整【D·正面，P4 FL-09 交叉】
- 删连接/删表/清空/网格删行/结构变更/导入删表六处全部 danger 确认，遮罩/Esc 取消。维持。

### UF-10 删除当前连接联动清空工作区【D·正面】
- ConnectionManager L110-113：删除当前选中连接 → onConnect(null) → resetWorkspaceState。状态一致性正确。维持。

## 五、小结

8 条核心流程中 4 条路径形态符合惯例（F1/F2/F4/F6 的骨架），但**可用性被两个链路级缺陷击穿**（UF-01 凭据、UF-03/06 对话框）；异常分支覆盖呈现「表单态好、工作区态差」的不均衡（UF-07），并有 2 个静默失败分支（loadDatabases、open()）。共 10 项（B5、C3、D2），其中 B 类新立 1 项（UF-02）、交叉 4 项（UF-01/03/05/06 与 PL-01/02/03 对应），其余与 P4 交叉引用。
