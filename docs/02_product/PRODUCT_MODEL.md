## 1. 产品定位

- 一句话定位（源 `docs/PRD.md` 2.1，经逆向报告引用）：「面向开发者、测试和运维的本地优先数据库客户端」。
- 产品形态：本地优先（local-first）的数据库工作台桌面应用（Tauri 2 单窗口 1400×900），首期聚焦 MySQL / MariaDB。
- 阶段目标（源 `README.md`「当前目标」）：先把 MySQL 工作台主流程跑顺——连接管理、Schema 浏览、SQL 编辑、结果面板、表数据基础能力；后续再逐步扩到更多数据库和更重的能力。
- 非目标/边界（源 `docs/RELEASE_CHECKLIST.md`）：
  - 不宣称支持 MySQL/MariaDB 以外的数据库（PG/SQLite 在 DEVELOPMENT.md 低优先级规划中）；
  - 结构对比仅「预览」：结构差异分析 + 结构变更 SQL 执行，非数据同步；
  - 备份/导入仅 SQL 格式；
  - 编辑门禁：结果面板仅「单表直查 + 单列主键」可编辑；数据网格仅单列主键表开放更新/删除。

## 3. 使用场景（源 PRD §3，共 6 组）

1. **首次使用**：新建连接 → 测试连接（延迟/版本/用户反馈）→ 保存 → 点击连接进入工作区。
2. **日常查询**：SQL 编辑器写 SQL（Ctrl+Enter 执行）→ 结果面板查看（多 Tab）→ 导出 CSV/JSON → 历史回溯。
3. **数据修正**：Schema 树点表 → 数据网格分页/筛选定位 → 双击编辑 / 新增行 / 勾选删除（均有确认或成功反馈）。
4. **表结构演进**：新建表（设计器）/ 修改既有表（diff 生成 ALTER）→ 保存后自动刷新 Schema。
5. **环境结构对齐**：结构对比选源/目标库 → 查看差异（表级 + 列级）→ 复制/导出 SQL 或危险确认后执行。
6. **安全底线**：备份导出 .sql → 必要时导入还原（可选先删现有表）。

场景级流程图与异常分支见 `docs/03_flow/USER_FLOW.md`（用户旅程）与 `docs/03_flow/BUSINESS_FLOW.md`（正常/异常/边界）。

## 4. 核心价值

> 以下为从上述来源事实归纳的价值表述（归纳自 PRD §1/§9 与 README「本地桌面体验」，非新增承诺）：

1. **本地优先安全**：无网络依赖；连接密码仅存系统钥匙串（connections.json 不落密码，有 Rust 单测锁定）；SQL 历史默认会话级、敏感词不落盘；危险操作六类强制二次确认。
2. **轻快的工作台闭环**：连接 → 浏览 → 查询 → 改数 → 导出 → 备份，单窗口内闭环；深色主题 SQL 工作台惯例交互（CodeMirror 6）。
3. **诚实的边界承诺**：能力边界（对比仅预览、备份仅 SQL、编辑门禁）在文档、设置面板、发布清单三处口径一致（PL-08 正面项）。
4. **面向扩展的克制**：Driver/Capabilities 抽象已预置（虽为空壳，IA-05），多库扩展路径已留。

## 5. 已知价值交付缺口（源评审，影响上述价值真实达成）

| 缺口 | 影响 | 编号 |
|------|------|------|
| 数据库凭据链路断裂（钥匙串密码「存而不取」，前端传参恒空密码） | 带密码账户「测试成功→使用失败」，核心承诺对这类用户不可用 | PL-01（B，最高优先级） |
| 原生文件对话框插件未注册 | 导出主路径损坏（走浏览器降级）；备份导入完全不可用 | PL-02（B） |
| SQL 执行无超时无取消 | 「执行中」态可能无终点 | UF-02（B） |
| 设计器未保存关闭无拦截 | 结构工作丢失风险 | PL-03（B） |

详见 `docs/06_review/UX_REVIEW.md` 与 `docs/product-review/PRODUCT_LOGIC_REVIEW.md`。
